# Testing

All tests are end-to-end under `tests/`. Do not add `#[test]` functions or
`#[cfg(test)]` modules in `src/`.

```
cargo nextest r --release
```

## Filetests

`tests/filetests/**/*.sir` run through `tests/filetests.rs`. The first line
picks the mode:

- `; test print`, `verify`, `parse-error`, `opt`: IR text and diagnostics.
- `; test wasm`, `x86_64`, `x86_64-vcode`, `x86_64-hex`: backend output.

Checks are `filecheck` directives in comments. Files with the
`NOTE: Assertions have been autogenerated` line are regenerated with:

```
tools/update_filecheck.py <file|dir|glob>
```

Add `--force` to take over a hand-written file. Review the diff afterwards.

## Execution tests

Rust tests compile a function and run it: wasm through wasmi, x86_64 through an
mmapped buffer or a linked C harness. Shared references and sample values live
in `tests/common/mod.rs`. `tests/int_widths.rs` runs every op at every width on
both backends against a Rust reference.

## Lessons

- Runtime crates stay in `[dev-dependencies]`.
- Narrow-type params can't be used to test narrow ops from Rust, because the
  caller controls upper bits. Take `i64` params and `ireduce` inside the
  function; this also exercises garbage upper bits.
- When a feature makes a negative filetest legal (for example `icmp` on `i8`),
  change the input rather than the expected error.
