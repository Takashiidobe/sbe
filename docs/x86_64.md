# x86_64 backend

`x86_64::compile(&func)` returns code bytes, asm text, and (via `to_object`) an
ELF relocatable. Stages: `lower` (sir to `VCode<Reg>`), `allocate`
(`VCode<PReg>`), `emit` (iced-x86).

## Calling convention

System V integer args in `rdi, rsi, rdx, rcx, r8, r9`, result in `rax`. Only
caller-saved registers are allocated, so there is no prologue or epilogue.
Functions may have up to six params and one return value.

## Calls

`compile_module` compiles each function; `module_object` writes them into one
ELF relocatable. A call moves args into the argument registers, emits
`call rel32` with a zeroed field, and records a `Reloc`; the object file turns it
into an `R_X86_64_PLT32` against the callee's name, so imports are left
undefined for the linker.

A call clobbers every caller-saved register. In a function with calls, values
live across one must sit in `rbx, r12-r15`; the allocator only offers those
registers when a call exists, so leaf functions are unchanged. Used callee-saved
registers are pushed in the prologue and popped before each `ret`. With an even
number of pushes, 8 extra bytes keep `rsp` 16-byte aligned at calls.

## Memory

`load` and `store` map to `mov` of the access width (`movzx` for 8 and 16 bit
loads). Stack slots sit at the bottom of the frame: the prologue pushes the used
callee-saved registers, then subtracts the slot bytes plus any padding needed to
keep `rsp` 16-byte aligned, and `stack_addr` is `lea reg, [rsp + offset]`. A
function with slots gets a frame even if it makes no calls.

## Floats

Float values live in the general registers as bit patterns, so the allocator
needs no second register class. Each float op moves its operands into `xmm0` and
`xmm1`, computes there, and moves the result back, which costs extra moves.
`fcmp` uses the `cmpsd`/`cmpss` predicates (`eq`, `lt`, `le`, `neq`; `gt` and
`ge` swap operands) followed by `and 1`, so NaN handling needs no flags.
`fcvt_to_sint` is `cvttsd2si`, which yields `i64::MIN` out of range.

Floats are passed and returned as in system v: ints in `rdi..r9`, floats in
`xmm0..xmm7`, counted separately, result in `rax` or `xmm0`.

## Switch and traps

`switch` is a compare chain: for each case, `mov tmp, key`, `cmp`, `je`, then a
`jmp` to the default. The value is zero-extended first when narrower than 64
bits. Edges with block args get their own move block, as for `brif`. `trap` and
`unreachable` emit `ud2`. A jump table is not implemented.

## Register allocation

Linear scan with no spilling. A value gets one interval covering everything
where it is live. Running out of the nine registers (fourteen in a function with calls) is a `CompileError`, not a
fallback.

## Integer widths

Narrow values sit in 64-bit registers with undefined upper bits. `Inst::Ext`
(`movsx`, `movsxd`, `movzx`, or `mov r32, r32`) makes a clean copy into a fresh
vreg before compares, divides, right shifts and extends. Narrow divides then run
as 64-bit `idiv`/`div`, so overflow wraps with no trap.

## Lessons

- `idiv` raises #DE, which can't be caught in-process. Execution tests skip
  inputs that trap.
- Shifts need the count in `cl`. For narrow types the count is first ANDed with
  `width - 1`; plain 64-bit `shl` would use `count mod 64`.
- `setcc` writes one byte, so it is always followed by `movzx`.
- Fixed registers (`rax`, `rdx`, `rcx`) appear as `Reg::P` in `VCode`. The
  allocator treats their intervals as busy, which keeps vregs away from them.
- Edge moves for `brif` go in their own blocks, and `parallel_moves` breaks
  cycles with a fresh vreg.
- Fresh vregs start at `func.num_values()`; thread `next_vreg` through any
  helper that creates temporaries.
